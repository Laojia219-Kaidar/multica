# HiveCrew visual acceptance v2

The current HiveCrew visual system is the authority. New surfaces must reuse its tokens, primitives, layout rhythm, typography, navigation structure and interaction patterns.

## Required journeys

1. Sidebar and global navigation: Chinese labels, active state, collapse state and deep-link refresh.
2. Project and Issue: current status, responsible employee, active Task/Run, blocker, receipt and result ownership.
3. Digital employee and organization department: one employee identity, exact Runtime/model/base binding and current work.
4. Work wall: green terminal cards sourced from live Task/Run events, not fabricated terminal text.
5. Outcome Center: Project→Issue→Task→Comment/Attachment→Outcome lineage and reverse links.
6. Bases and usage: host/runtime health and model/account/employee usage remain truthful and do not duplicate employee health cards.

## States and evidence

Every journey must capture real-data, empty, loading and error states in both wide and narrow layouts. Evidence includes URL, revision, timestamp, screenshot and a DOM/interaction assertion. A screenshot without a repeatable journey is visual reference only.
